# Module 03 — Sửa code đơn giản và đúng phạm vi

- Dùng thay đổi nhỏ nhất đáp ứng yêu cầu. Không thêm feature, configurability hoặc refactor ngoài scope. Tránh abstraction cho một lần dùng và xử lý phòng thủ cho trường hợp không thể xảy ra. Mỗi dòng sửa phải phục vụ yêu cầu.
- Triết lý kỹ sư tối giản & Thang 7 nấc thẩm định code (Senior Dev's Ladder of Laziness — Ponytail standard): Đoạn code tốt nhất là đoạn code không bao giờ phải viết; ưu tiên loại bỏ code thừa (-N) hơn là viết thêm code mới (+1). Trước khi viết code hoặc bổ sung tính năng, BẮT BUỘC thẩm định tuần tự qua 7 nấc: (1) Cần thiết (YAGNI): Đoạn code này có thực sự cần thiết cho mục tiêu hiện tại không? Tuyệt đối không phỏng đoán nhu cầu tương lai để viết sẵn; (2) Tái sử dụng: Kiểm tra codebase hiện tại đã có hàm, utility hoặc pattern tương tự chưa; tái sử dụng tối đa thay vì viết mới; (3) Thư viện chuẩn (Stdlib): Thư viện có sẵn của ngôn ngữ (Python, JS, Go...) có xử lý được không? Ưu tiên tuyệt đối thư viện chuẩn; (4) Nền tảng native: Trình duyệt/Hệ điều hành có sẵn tính năng không (HTML5 semantic tags, modern CSS, shell commands...); (5) Phụ thuộc hiện có: Các dependency đã cài trong dự án có giải quyết được không? Nghiêm cấm tự tiện cài thêm package ngoài (npm/pip) cho các tác vụ nhỏ lẻ; (6) Tối giản logic: Viết code mạch lạc, dễ đọc, dễ bảo trì, cấm đẻ ra các class bọc, singleton hay abstraction một lần dùng thừa thãi (Over-Engineering); (7) Mức tối thiểu: Khi bắt buộc phải viết, chỉ viết đúng lượng code nhỏ nhất đủ để thỏa mãn yêu cầu và pass kiểm thử.
- Giữ style và cấu trúc xung quanh. Không format hoặc dọn code không liên quan. Dọn imports/variables/functions do thay đổi của mình làm thừa; chỉ báo dead code có sẵn, không tự xóa.
- Khi sửa bug: tái hiện, xem log, xác định nguyên nhân rồi sửa. Không thay đổi rộng chỉ dựa vào phỏng đoán.
- Chuẩn hóa Khởi tạo và Định vị Dự án (Project Entry & AGENTS.md Standard): Mọi dự án khi được khởi tạo hoặc bắt tay vào làm việc BẮT BUỘC phải có file `AGENTS.md` tại thư mục gốc của dự án. File này phải chỉ rõ: (1) Mục tiêu và bản chất dự án; (2) Tech-stack chính; (3) Các lệnh thực thi cơ bản (`dev`, `build`, `test`); (4) Cấu trúc thư mục trọng yếu. Nhờ đó, bất kể AI Agent nào mở dự án trong tương lai đều nắm bắt ngữ cảnh ngay lập tức mà không cần hỏi lại hay phỏng đoán.
- Hợp đồng Thiết kế Giao diện Tự động (Zero-Friction DESIGN.md): Bất cứ khi nào nhận yêu cầu tạo mới hoặc sửa giao diện (Web, App, Dashboard, Landing page... dù người dùng chỉ nói ngắn gọn "làm web đi", "dựng giao diện", "code trang này" hay không hề nhắc tên file), AI BẮT BUỘC TỰ ĐỘNG kiểm tra và khởi tạo file `DESIGN.md` ở gốc dự án. AI tự động suy luận bảng màu, font chữ phù hợp với lĩnh vực dự án, kết hợp cùng các skill thẩm mỹ để loại bỏ 100% AI Slop mà không cần người dùng phải nhắc.
- Quy chuẩn Kỹ năng Chuyên biệt theo Dự án (Project-Scoped Skills): Các kỹ năng chuyên biệt chỉ nạp vào dự án có liên quan (trỏ/symlink vào `.agents/skills/` của dự án đó), không nạp bừa bãi vào Global Context gây tràn bộ nhớ token và loãng chú ý của Agent.
- Xử lý tài liệu và dữ liệu cấu trúc: Giữ định dạng đầu ra chuẩn mực (với tài liệu văn phòng, tham chiếu quy chuẩn ECMA-376 tại `packs/office-openxml/RULE.md`). Chạy kiểm chứng mở file thành công trên ứng dụng thực tế trước khi báo hoàn thành nhiệm vụ.
